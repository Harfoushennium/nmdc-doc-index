# One-time host and repository setup

For each authorized repository, reuse its existing AGENTS.md, CLAUDE.md, GEMINI.md, project instructions and tracker conventions. Add the short rule below in the actual root instruction file(s) loaded by each participating harness, preserving other instructions. Check existing rules first, reconcile conflicts and verify read-back. Store a canonical skill directory in the repository or the harness's supported skill directory; avoid copying the full procedure into every root file. If installed globally, still add the project pointer and parent tracker link when initializing a repository. For web chats, use the enabled personal/workspace skill or existing Chief of Staff routing and a connected GitHub account; a chat lacking the skill/repo context cannot be guaranteed to invoke it. Establish repo identity through the project or explicit repository selection once. No repeated custom prompt is needed in configured environments.

**Root instruction block**

> For substantive project work, resumption, review, progress checks and handoff, automatically load `cross-harness-continuity` (repository skill at `.agents/skills/cross-harness-continuity/SKILL.md` or installed equivalent). GitHub is authoritative. Before changes, verify the current remote baseline and publish a start checkpoint. For each coherent authorized slice, test, commit, push, verify remote SHA and record evidence; checkpoint during execution and before handoff. Maintain the existing parent/workstream dashboards. Preserve agent provenance and independent QA; follow owner-only merge/release gates. If remote publication is unavailable, mark work UNPUBLISHED/BLOCKED. Never rely on chat memory or local-only commits as shared truth.

Codex and Antigravity: repository `.agents/skills/cross-harness-continuity/` and `AGENTS.md` are the preferred shared paths where supported. Claude Code: root CLAUDE.md points to canonical repository skill, or expose it under `.claude/skills/` using its supported installation method. Other IDEs/agents: use their actual documented always-on repository or global rules and skill folders. Do not guess installation paths or claim installation on a remote host. Verify discovery in a fresh session. Update project docs and tracker once; no mandatory new issue if an existing parent already covers it.

Optional deterministic check: execute `python <skill-dir>/scripts/verify_checkpoint.py --repo <local-checkout> --remote origin --branch <assigned-work-branch>` before handoff. It reads live remote refs and local Git status only, never writes or pushes. It cannot force an agent to publish, guarantee successful sync, enforce timer behavior or independently validate tests. Use host-approved hooks if the owner explicitly authorizes and the harness supports them; prefer a non-destructive handoff check over blind auto-commit/push. Protect secrets, local scratch files and owner-controlled branches. Do not weaken permission policies. Verify behavior with a fresh local and web session, publish a small authorized test slice, then hand off to another harness and compare exact remote SHA/evidence. If any environment lacks access, record limitation explicitly.
