# NMDC V2 standalone development candidate — increment 02

Not production accepted. Use the Windows CI artifact, not this source folder, for standalone testing. Extract the entire application ZIP and double-click Launch.exe. A supported existing browser is used; Python, pip, Excel, Node and separate WebView2 installations are not required by the packaged app. Runtime data is stored in a separate local NMDCIndexV2 folder under LOCALAPPDATA. Do not use production state or sole copies of DATA until independent acceptance.

This increment integrates the existing engine for scan, proposal-bound saved choices and durable drafts, approval (conservative no overrides), approved index views, undo, search, one-table XLSX/CSV/JSON export, persistent export profiles and column order, classification-rule editing, permanent source scope and sequential parser report creation. Reports default to a separate NMDC_V2_Reports/PARSER_FIX_REPORTS folder next to the local workspace parent; final location is pending. Report generation keeps flags OPEN and never approves. Changes to rules/scope require a new scan. Export uses browser download destination. Native HTTPS document links supported; local/UNC link click tests outstanding and source paths retained as text. CSV is formula-prefix neutralized; JSON preserves literal raw values.

Outstanding production scope: derived SQLite, grouping/saved index views, immediate safe cancellation and restart recovery, custom fields, remaining config migration, complete flag decisions and change-details expansion, overflow partitioning, backup/rollback, actual local source hyperlink behavior, security hardening, full feature parity and independent Windows/real-corpus acceptance. No production cutover or legacy issue closure.

Build only on Windows using the standalone candidate workflow. Developer tools are build-only, not user prerequisites. No operational DATA belongs in the package. The separate corpus diagnostic uses only the existing checkout read-only and emits aggregate metrics, not records.
